1. Introdução

1.1. Sobre o BookHub

O BookHub é uma aplicação web desenvolvida para proporcionar aos usuários um espaço centralizado para descoberta, organização e interação com livros. O sistema permite consultar informações sobre obras literárias e oferece recursos para que cada usuário possa registrar suas preferências e interagir com os livros disponíveis na plataforma.

A aplicação foi desenvolvida seguindo uma arquitetura composta por frontend, backend e banco de dados, permitindo a separação entre a interface utilizada pelos usuários, as regras e funcionalidades da aplicação e o armazenamento das informações.

Entre as principais funcionalidades disponibilizadas pelo sistema estão o gerenciamento de usuários, consulta de livros, autores e gêneros, avaliações, resenhas, favoritos e organização de livros em uma estante pessoal. O sistema também possui mecanismos de autenticação e controle das operações realizadas pelos usuários.

O BookHub foi desenvolvido utilizando tecnologias voltadas ao desenvolvimento de aplicações web, com HTML, CSS e JavaScript no frontend, Python e FastAPI no backend e PostgreSQL como sistema gerenciador de banco de dados. A comunicação entre a interface e o backend ocorre por meio da API desenvolvida com FastAPI.

O projeto foi estruturado de forma modular, buscando facilitar a manutenção, a organização do código e a futura inclusão de novas funcionalidades. A documentação técnica apresentada neste manual tem como finalidade apresentar essa estrutura e orientar a configuração, execução, manutenção e evolução do sistema.

1.2. Objetivo do sistema

O principal objetivo do BookHub é disponibilizar uma plataforma web que permita aos usuários descobrir, consultar, organizar e registrar informações relacionadas às suas leituras, reunindo diferentes recursos em um único ambiente.

Por meio do sistema, o usuário pode consultar livros disponíveis na plataforma, conhecer informações relacionadas a autores e gêneros e registrar suas próprias interações com as obras. Entre essas interações estão a atribuição de avaliações, a publicação de resenhas, a adição de livros aos favoritos e a organização das obras em sua estante pessoal.

Além das funcionalidades voltadas à experiência do usuário, o projeto tem como objetivo aplicar, de forma integrada, conceitos de desenvolvimento web, desenvolvimento de APIs, modelagem e gerenciamento de bancos de dados e arquitetura de software. A separação entre frontend, backend e banco de dados busca proporcionar uma estrutura organizada e facilitar a manutenção e a evolução da aplicação.

Dessa forma, o BookHub procura oferecer uma solução que combine organização de informações bibliográficas e interação dos usuários, ao mesmo tempo em que serve como aplicação prática dos conhecimentos técnicos utilizados em seu desenvolvimento.

1.3. Público-alvo do sistema

O BookHub é destinado principalmente a pessoas que possuem interesse em livros e que desejam utilizar uma plataforma para consultar, organizar e registrar suas experiências de leitura. O sistema foi desenvolvido para atender usuários que buscam centralizar informações sobre as obras que conhecem ou pretendem ler, além de registrar avaliações, resenhas, favoritos e organizar livros em sua estante pessoal.

A aplicação também considera diferentes níveis de familiaridade dos usuários com ferramentas digitais, buscando disponibilizar uma interface simples e intuitiva para a realização das principais operações do sistema.

Embora o público-alvo da aplicação seja composto pelos usuários finais interessados em livros, este Manual Técnico é direcionado principalmente a desenvolvedores, estudantes e responsáveis pela manutenção ou evolução do projeto. O documento apresenta informações sobre a arquitetura, tecnologias, estrutura de arquivos, configuração, execução e funcionamento dos principais componentes do BookHub.

Dessa forma, o manual serve como uma referência técnica para compreender a implementação atual do sistema e fornecer suporte para futuras correções, manutenções e implementações de novas funcionalidades.

2. Visão Geral da Arquitetura

2.1. Arquitetura do sistema

O BookHub utiliza uma arquitetura dividida em três camadas principais: frontend, backend e banco de dados. Essa organização permite separar as responsabilidades da aplicação, facilitando o desenvolvimento, a manutenção e a evolução do sistema.

A primeira camada corresponde ao frontend, responsável pela interface com a qual o usuário interage. Essa camada foi desenvolvida utilizando HTML, CSS e JavaScript, sendo responsável pela apresentação das informações, pela interação com o usuário e pelo envio de solicitações ao backend.

A segunda camada corresponde ao backend, desenvolvido em Python utilizando o framework FastAPI. Essa camada concentra as regras e funcionalidades da aplicação, recebe as requisições realizadas pelo frontend, realiza as validações necessárias, processa as operações solicitadas e retorna as respostas ao cliente.

O backend apresenta uma organização modular. Os routers são responsáveis pela definição e organização dos endpoints da API de acordo com suas funcionalidades. Os schemas são utilizados para definir e validar os dados recebidos e enviados pela API. Os models representam as entidades utilizadas pela aplicação e sua relação com as estruturas do banco de dados. A comunicação com o banco é realizada por meio do SQLAlchemy, utilizado como ferramenta de mapeamento objeto-relacional (ORM).

A aplicação também possui uma camada relacionada à segurança e autenticação, concentrada principalmente no módulo security.py. Essa estrutura é responsável pelos mecanismos utilizados para proteger o acesso às funcionalidades que exigem autenticação.

A terceira camada corresponde ao banco de dados, implementado utilizando o PostgreSQL. É nessa camada que são armazenadas as informações persistentes do sistema, incluindo dados relacionados a usuários, livros, autores, gêneros, avaliações, resenhas, favoritos e organização da estante.

A comunicação entre frontend e backend ocorre por meio de requisições HTTP, utilizando a API. O backend, por sua vez, realiza as operações necessárias no banco de dados e devolve ao frontend as informações resultantes da solicitação.

A separação dessas responsabilidades permite que cada camada seja desenvolvida e mantida de maneira mais independente, contribuindo para uma estrutura organizada e facilitando futuras alterações ou ampliações do BookHub.

2.2. Comunicação entre as camadas

A comunicação entre as camadas do BookHub ocorre de forma sequencial, tendo o frontend como ponto de interação com o usuário e o backend como intermediário entre a interface e o banco de dados. Essa organização permite que o frontend não acesse diretamente o banco, mantendo as regras de negócio e o controle das operações concentrados no backend.

Quando o usuário realiza uma ação na interface, como consultar um livro, registrar uma avaliação ou adicionar uma obra aos favoritos, o JavaScript do frontend prepara e envia uma requisição HTTP para o endpoint correspondente da API. Os dados necessários para a operação são enviados de acordo com o formato esperado pelo endpoint.

Ao receber a requisição, o FastAPI identifica o endpoint responsável pela operação e encaminha a solicitação para o componente correspondente dentro do backend. Os schemas participam desse processo realizando a validação e a estruturação dos dados recebidos, garantindo que as informações estejam de acordo com os formatos definidos pela aplicação.

Após a validação, o backend executa a lógica necessária para realizar a operação solicitada. Quando a operação envolve informações armazenadas no banco de dados, os models e o SQLAlchemy são utilizados para consultar, inserir, atualizar ou remover os registros necessários no PostgreSQL.

Depois que a operação é concluída, o backend constrói uma resposta e a envia de volta ao frontend, normalmente utilizando o formato JSON. O JavaScript recebe essa resposta, interpreta os dados retornados e atualiza a interface de acordo com o resultado da operação.

Usuário → Frontend → API / FastAPI → Routers → Schemas / Validação → Models / SQLAlchemy → PostgreSQL → Backend → Frontend → Usuário

Essa estrutura estabelece uma comunicação organizada entre as diferentes partes do sistema e evita que as responsabilidades sejam concentradas em uma única camada. O frontend fica responsável pela apresentação e interação, o backend pelo processamento das operações e o banco de dados pelo armazenamento persistente das informações.

Além disso, a utilização de uma API como intermediária permite que o backend possa ser consumido por diferentes clientes no futuro, sem que seja necessário modificar diretamente a estrutura do banco de dados para cada nova interface.

2.3. Fluxo geral da aplicação

O funcionamento do BookHub segue um fluxo baseado na interação entre o usuário, o frontend, a API, o backend e o banco de dados. A partir de uma ação realizada na interface, a solicitação percorre as diferentes camadas do sistema até que a operação seja processada e o resultado seja apresentado novamente ao usuário.

De forma geral, o fluxo de uma operação pode ser representado pelas seguintes etapas:

  1. Interação do usuário: o usuário realiza uma ação no frontend, como consultar um livro, realizar uma avaliação, publicar uma resenha, adicionar um favorito ou organizar uma obra em sua estante.
  2. Envio da requisição: o JavaScript do frontend identifica a ação realizada e envia uma requisição HTTP para o endpoint correspondente da API.
  3. Recebimento pelo backend: o FastAPI recebe a requisição e direciona a solicitação para o router responsável pela funcionalidade.
  4. Validação dos dados: os dados recebidos são analisados de acordo com os schemas definidos para a operação. Quando necessário, também são verificadas as informações relacionadas à autenticação e autorização do usuário.
  5. Processamento da operação: após as validações, o backend executa as regras necessárias para realizar a operação solicitada.
  6. Acesso ao banco de dados: quando a operação necessita consultar ou modificar informações persistentes, o SQLAlchemy realiza a comunicação com o PostgreSQL por meio dos models correspondentes.
  7. Retorno da operação: após o processamento, o backend gera uma resposta contendo o resultado da solicitação e a envia ao frontend, utilizando o formato JSON.
  8. Atualização da interface: o JavaScript recebe a resposta da API, processa as informações retornadas e atualiza a interface de acordo com o resultado da operação.
  9. Apresentação ao usuário: o resultado final da operação é apresentado na interface do BookHub, permitindo que o usuário tenha conhecimento do resultado de sua ação.

Esse fluxo pode ser resumido da seguinte maneira:

Usuário → Frontend → Requisição HTTP → FastAPI → Router → Schema / Validação → Processamento → SQLAlchemy / Model → PostgreSQL → Resposta JSON → Frontend → Usuário

Por exemplo, quando um usuário registra uma avaliação para um livro, a ação é realizada na interface do frontend. O JavaScript envia os dados da avaliação para o endpoint correspondente da API. O backend recebe e valida essas informações, verifica os requisitos necessários para a operação e utiliza os componentes responsáveis pelo acesso aos dados para registrar a avaliação no PostgreSQL. Após a conclusão da operação, uma resposta é enviada ao frontend, que apresenta ao usuário o resultado da ação.

Esse fluxo é utilizado como base para as diferentes funcionalidades do sistema, variando apenas os endpoints, dados e operações envolvidos em cada caso. A separação das responsabilidades permite que o processamento das informações ocorra de maneira organizada e que cada camada desempenhe uma função específica dentro da aplicação.
